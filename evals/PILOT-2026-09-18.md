# Pilot comparison, 2026-09-18

A first small three-condition run. **It is a pilot, not a benchmark.** Two
repetitions per cell on one model is far too little to support an efficacy
percentage, and the review below was not blind. Read the limitations before
quoting any number.

## Setup

| Item | Value |
| --- | --- |
| Agent | Claude Code 2.1.258, headless `claude -p` |
| Model | `claude-opus-5`, default effort |
| Cases | 4 pairs: 01/14, 03/13, 05/06, 08/09 |
| Conditions | `baseline`, `one-line`, `skill` |
| Repetitions | 2 per case and condition, 48 runs total, order shuffled with a fixed seed |
| Isolation | Fresh session per run; `--setting-sources project` in a directory with no project settings, `--disable-slash-commands`, `--strict-mcp-config`, `--no-session-persistence`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. No skill installed in the host: the `skill` condition supplies `SKILL.md` in the prompt only. |
| Workspace | Each run works in a copy outside this repository, so `case.json`, `oracle.py`, and `reference/` are unreachable. |
| Tools | `Bash,Read,Edit,Write,Glob,Grep`, permission mode `acceptEdits` |
| Failures | None. 48/48 finished, no timeouts, mean 17 seconds per run. |

Raw artifacts (diff, transcript, report, run metadata) stay in the ignored
`.eval-runs/pilot-1/` directory and are not published here.

## What the runs actually did

- **Restraint cases behaved identically in every condition.** For 01, 03, 06,
  08, and 14 all 18 runs of each case produced a byte-identical diff. On this
  model the restraint cases did not discriminate at all: baseline already
  reused existing coverage, and case 06 reused the pre-existing failing
  regression rather than duplicating it.
- **05 (missing regression):** every run fixed the comparison and added boundary
  coverage. Baseline added a second past-expiry test on top of the boundary
  test; the boundary test alone already fails on the original bug.
- **09 (authorized edge):** all runs implemented the authorized default and
  added one focused test. One baseline run also added
  `test_keyword_argument_is_raw`, which freezes a parameter name as a
  keyword-argument contract the task never authorized. That is the only
  invented requirement in the pilot.
- **13 (public contract):** the most informative case. Baseline covered the new
  key, non-zero precedence, and zero precedence (6 and 12 lines). Skill covered
  the new key plus zero-valued precedence in two assertions. One-line added a
  single assertion covering only zero-valued precedence, leaving plain new-key
  acceptance untested — thinner than the case's stated review criteria, though
  the acceptance subset still passes.
- Every run ran the test suite before finishing; no run deleted, skipped, or
  weakened an existing assertion.

## Reading

On this model and these eight cases, the skill reduced test additions relative
to baseline (2.81 to 1.50 mean added lines, concentrated in two cases) without
any loss of correctness or required coverage, and avoided the one invented
requirement baseline produced. The one-sentence instruction produced a
comparable line count while being the only condition to leave an authorized
contract point uncovered in case 13.

That is a plausible-looking direction, nothing more. With two repetitions per
cell, five of eight cases showing zero variance, and an unblinded reviewer, the
sensible conclusion is that the harness works end to end and that a larger run
is worth doing — not that the skill has a measured effect size.

## Limitations

- Two repetitions per cell, one model, one host, one Python evaluation set.
  No statistics were computed and none would be meaningful here.
- The review was performed by the same agent that operated the harness, with
  full knowledge of condition. An independent blind reviewer would be better.
- Only 8 of the 14 cases ran. Cases 02, 04, 07, 10, 11, and 12 were not exercised,
  including the ambiguity case, which is the one requiring a clarifying question.
- The `skill` condition supplies the skill text in the prompt. This measures the
  skill's content when loaded, not host activation, which remains untested.
- Baseline behavior here is a strong baseline: this model already showed
  restraint on mechanical changes without any instruction. A weaker or more
  eager model could produce a very different spread.

## Reproduce

The driver used for this pilot is `.eval-runs/pilot-driver/pilot.py` (ignored by
git; it is a local convenience, not part of the harness). It calls
`evals/run.py prepare`, runs each prepared prompt in an isolated copy, copies the
result back, and calls `evals/run.py inspect`.
